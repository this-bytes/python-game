ARCHITECTURE ACHIEVED
================================================================================

Tab Content Structure:
├─ Dashboard Tab → Dashboard Panel (UIProvider widgets from all plugins)
├─ Operations Tab → Specialist Roster (team management)
├─ Incidents Tab → Incident Queue (unassigned incidents)
├─ Specialists Tab → Specialist Roster (alternative team view)
└─ Analytics Tab → Placeholder "Coming Soon"

Component Reuse (No Duplication):
├─ specialist_roster (single instance)
│  ├─ Used by Operations tab
│  └─ Used by Specialists tab
├─ incident_queue (single instance)
│  └─ Used by Incidents tab
└─ dashboard_panel (single instance)
   └─ Used by Dashboard tab

Event Flow:
1. User clicks tab → active_tab updates
2. Event published → "ui_tab_changed"
3. Next frame → conditional rendering
4. Only active tab renders → specialist_roster.draw(), etc.

Data Change Flow:
1. Game system changes state → e.g., specialist hired
2. Event published → "specialist_hired"
3. GameUI receives event → _on_data_changed() logs it
4. Next frame → reads fresh game_state
5. Updated data displayed → new specialist visible
